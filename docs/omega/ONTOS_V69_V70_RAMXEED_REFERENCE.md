## Source provenance, deduplication and limits

Authoritative hardware data: RAMXEED, **MB85RQ8MX**, DS501-00074-1v1-E, pages 1–7. The two attached datasheet files have **identical SHA-256** (`75eb9d2408e33107e1834c...`); they are not independent confirmations. The 2026 RAMXEED product catalog describes broader FeRAM / ReRAM families. The anti-counterfeit marketing text describes **specialized** FeRAM PUF/ASIC solutions; it must not be generalized to commodity MB85RQ8MX, and its readable unique ID (RUID 0x4C) is not cryptographic proof of unclonability. Source marketing performance numbers are not independent engineering measurements.

Datasheet (p.1): 8 Mbit = 1,048,576 bytes; Quad SPI 108 MHz, 54 MB/s advertised transfer bandwidth; VDD 2.7–3.6 V; maximum operating 18 mA in Quad I/O at 108 MHz; maximum standby 180 µA, DPD 10 µA, hibernation 5 µA; rated read/write cycles 1e14 @ +85°C and 1e13 @ +105°C; data retention 10 years @ +105°C and 95 years @ +55°C. Catalog (p. 4–5) contains general FeRAM write-cycle timing of 120 ns, **not an interchangeable maximum per-command latency for MB85RQ8MX**. The usage slides (pp. 13–15) show historical application scenarios, not integration tests of this repository.

## Implementation boundaries

- `omega_x_evolution/ontos_v69_substrate.py`: immutable validated `PowerComponents`, `SubstrateScenario` for exactly six declared L11 substrate **categories** (H100_FP8, RRAM_PCM, SOT_MRAM, PBIT_SMTJ, SILICON_PHOTONICS, QPU_QLDPC). `P_wall = (P_core + P_memory + P_ADC + P_DAC + P_network + P_host) / eta_PSU + P_cooling + P_aux`. Only explicitly populated, disjoint rails produce a wall result; unknown inputs propagate `None`. Relative uncertainty is input sensitivity, not a calibrated confidence interval; watts and joules are separated. Output `physical_measurement_verified=false` for all scenarios. The six categories share a generic metrological boundary only: **there is no native ADC/DAC, cryocooler, optical or QPU model/calibration claim**.
- `FeRAMSegment` + `FeRAMSupplyScenario`: optional MB85RQ8MX peripheral **VDD energy upper envelope** using per-mode maximum currents, supply voltage and modeled time. Checks the ideal advertised 54 MB/s transfer ceiling. No PCIe, SPI opcode/dummy-cycle, PCB regulator, bus-controller, host or PSU overhead inferred. `wall_energy_j=None` until the operator supplies a disjoint whole-system model. Using max state current as a scenario envelope is conditional on specified operating modes, not an observed actual draw.
- `omega_x_evolution/ontos_v70_endurance.py`: sparse per-address read/write-cycle bookkeeping, immutable revisions, exact 85°C/105°C rating points, and fail-closed budget exhaustion. Other temperatures are **UNKNOWN**, not interpolated. The interrupted serial-access fixture applies a **prefix of bytes**: FeRAM non-volatility does not imply multibyte transaction atomicity or crash-consistent checkpointing. Read and write accesses are conservatively charged to the same cycle budget; actual cell-disturb behavior is not measured.
- Worst-case 100 Hz * 5 years * 365.25 days/year = 15,778,800,000 accesses to one byte; below the manufacturer's 1e13 @105°C numerical cycle qualification. This is only a **conditional finite model**, not a five-year system-life guarantee: thermal history, retention, power rail timing, board ESD, SPI bus, data scrubbing, ECC, long-term wear distributions, application write amplification and fault modes remain outside the model.

No production device driver, mTLS identity, cryptographic authentication, physical memory provisioning, execution of candidate code, release gate modification, or new cloud costs are introduced. A MAC/signature must use an independently protected key: FeRAM UID is not a secret and two copies/checkpoints without an external monotonic anchor cannot prevent rollback.
