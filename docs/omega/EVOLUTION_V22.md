# v22 — Asynchronous distributed MAP-Elites archipelago

Second new maintainer roadmap item. The actual archive and cascade are `engine.Archive` and `engine.Cascade`; v22 reuses both without modifying their source, rather than importing a nonexistent `omega_x_database`. The optional Ray backend runs one single-writer stateful actor per island. `await ObjectRef`, not `await ray.get(...)`, is used by the driver. `max_restarts=3`, `max_task_retries=3`, `max_concurrency=1`, and `max_pending_calls=2` are explicit. Ray restart reinitializes actors, so every bounded request carries its last authenticated, committed snapshot. The actor caches the archive and response for repeated requests and reconstructs from the supplied snapshot on cache miss. No checkpoint key is sent to any actor. Sources must match the driver contract. No arbitrary candidate Python is executed, and only offline mutation proposals are supported by this mode. This is a separate cluster runner, not a migration of the original engine's selection/budget semantics.

## Architecture and guarantees

- **Bounded scheduling:** 1–512 logical islands, 1–100 rounds, 1–16 proposals per island per round; total proposal budget 1–100,000 (at least one per island), total proposal+potential migration work <=100,000. Budget is split deterministically by island index; unlike v21's synthetic proposal credits these are proposal counts, not money. `parallelism` caps outstanding transactions (1–512). Local executors cap physical processes/threads at 32. Ray actor resource reservation is one CPU each, requiring enough available resources; total advertised CPU is checked but does not guarantee availability. Each request has a 1–3600 s driver wait deadline. No live LLM execution. No unlimited retry.
- **Asynchronous progression:** use `asyncio.wait(FIRST_COMPLETED)`; no round barrier across islands. Each actor independently runs a serial mutation batch while others progress. One in-flight request per island per driver. Independent actors use distinct deterministic RNG streams; timing of migrations affects evolution, so fresh asynchronous runs are not bit-for-bit deterministic. A failed/aborted uncommitted transaction can be recomputed without duplicating a committed revision. Cancellation prevents driver commit; it does not promise immediate cancellation of a running local CPU operation. A local process failure aborts the run; resume explicitly using a new backend. Ray system failures may be retried within the configured finite limits.
- **Local MAP-Elites state:** each actor owns one existing 10x10 descriptor grid with capacity four per Pareto cell, an append-only local lineage and its sampling `children` index. The external identity is `state.island` and each artifact ID is namespaced `i{island}-...`; the local `Artifact.island` index is zero. `Archive.sample` uses its original DGM/QD weights; mutation changes the genome under existing bounds. Seed and admitted programs have fixed objective metrics. Drivers maintain a summary of committed islands only. No global serial archive mutation.
- **Migration:** each island publishes its top fixed-score artifact at the configured local round interval and final evolution round. Its outbound packet is included atomically in its signed snapshot. Ring neighbor reads the latest committed packet at dispatch and consumes its source revision at most once. Intermediate packets can be intentionally coalesced if the destination is busy; this is a latest-value mailbox, not reliable delivery of every intermediate elite. One final drain round ensures the last published packet from each predecessor is considered, after evolving rounds finish. Imported programs are checked anew against destination properties and (if enabled) Stage 3b. Remote lineage references are recorded as an immutable migration receipt (`source`, `revision`, `origin_id`, local `id`), not a dangling local parent. A received/accepted immigrant may be dominated or duplicate and not retained in a Pareto front; report distinguishes seen, accepted and retained **at admission**. A later eviction does not change that receipt. No migration performed with a single island. No final-drain re-export, preventing cyclic infinite propagation.
- **Durability:** driver SQLite file (local, operator-controlled directory, O_EXCL/0600 initial creation) contains a signed metadata contract and a per-island snapshot with revision and HMAC-SHA256. Synchronous FULL, trusted_schema OFF, BEGIN IMMEDIATE and CAS protect individual updates. Each atomic transaction contains the archive, challenge state, counters, migration receipt and outbound packet, plus any latency evidence. No actor-side writes or distributed filesystem needed. Driver can reopen and resume unfinished rows from a new process. The store binds the Python version, source hashes of cluster/engine/workers/performance and all config fields; do not change seed/rounds/budget/policy on resume. Backend selection is not part of the contract, so supported backends may replace each other if code/config match. The state is checkpointed per island, not all-islands per generation. **Single driver only**, not distributed consensus or multi-driver HA; no protection against whole-database rollback/deletion, no anti-rollback oracle, no external replication. Snapshot cap 16 MiB/island; driver holds committed snapshots and rechecks newly admitted artifacts, which can bottleneck larger runs. No measured speedup claim.
- **Promotion integrity:** a trusted actor computes ordinary Stage 0–3 using bounded expressions. Driver validates counters, append-only lineage, namespaced ids, migrant origin/retention, genome bounds, mandatory challenge points, and archive summary, independently reevaluates every newly admitted candidate on the same public grid/challenge, then commits. Rejected proposals are not independently replayed. A malformed worker response cannot directly set accepted fitness. Adaptive challenge failure counts and timing evidence still rely on trusted worker code. Ray is not an untrusted-worker protocol or sandbox: membership can execute Python/pickle; only deploy on a private, operator-controlled cluster with access controls/network isolation. No checkpoint key distributed, but a compromised Ray cluster is not assumed safe. For untrusted remote evaluation use the existing separate authenticated HTTP protocol and its independent recomputation. No holdout samples sent in snapshots; the fixed benchmark seed is public and the fixed fixture is not a secret test against hostile insiders. Driver alone uses holdout for the final report.
- **v21:** `--performance-regression` enables same-host paired parent + cell/global champion p50/p95/p99 gate before admission for candidates and immigrants, not across heterogeneous-host historical raw times. Driver verifies the accepted record's workload/runtime hashes, reference identities and decision arithmetic. Timing samples themselves are trusted from the actor, not remeasured on a different host. v21 policy unchanged and retains the total 1024-attempt cap including worst-case migration attempts. This can constrain very large measured campaigns; default deterministic operation-proxy mode remains unchanged, and cluster scheduling itself is still nondeterministic. No automated SFT/DPO export or live cost-router integration from this new path.

## Use and deployment

```sh
# In a private directory; create once, then protect/store the key separately.
python -c 'import os,secrets; f=os.open("cluster.key",os.O_CREAT|os.O_EXCL|os.O_WRONLY,0o600); os.write(f,secrets.token_bytes(32)); os.close(f)'
python -m omega_x_evolution.cluster --backend process --islands 16 --rounds 4 --batch 2 --budget 128 --parallelism 4 --db cluster.db --key-file cluster.key --stop-after 20
# Identical settings except stop/resume:
python -m omega_x_evolution.cluster --backend process --islands 16 --rounds 4 --batch 2 --budget 128 --parallelism 4 --db cluster.db --key-file cluster.key --resume
```

`--stop-after` counts new committed operations in the current invocation; report `commits` is cumulative and includes final drain commits. For a larger logical simulation use `--backend simulation --islands 256 --rounds 2 --batch 2 --budget 1024 --parallelism 32 --migration-interval 1` with a new database. This is a single process with threads and does **not** demonstrate distributed machine capacity.

Install identical Python patch version and OMEGA-X source on each trusted Ray node. Install the optional `cluster` extra (Ray 2.x; installation still requires existing project dependencies). Provision head and workers through the operator's Ray infrastructure, keep service ports private, run the driver on a cluster node. The CLI does not provision, expose, or scale cloud resources and does not use Ray Client URLs. `--ray-address auto` attaches to an existing cluster; `local` explicitly starts a local Ray runtime; `existing` is for a previously initialized Ray session in the Python API. `SPREAD` is best effort, not one physical machine per island. `--distinct-nodes` requires enough live CPU nodes and uses hard `NodeAffinitySchedulingStrategy` with observed node IDs checked, one island per distinct Ray node ID. Ray nodes may share a physical host; actual machine independence remains operator responsibility. Hard affinity may prevent restart on a vanished node; reopen the store with a new driver and enough replacement nodes. In default spread mode actor recreation may be placed elsewhere by Ray; config/source and input snapshot are rechecked. No claim of autoscaling/HA, zero-downtime node loss, or exactly-once physical computation. Actor retries may recompute; durable CAS prohibits duplicate committed revisions.

```sh
python -m pip install '.[cluster]'
python -m omega_x_evolution.cluster --backend ray --ray-address auto --distinct-nodes --islands 128 --rounds 2 --batch 2 --budget 512 --parallelism 128 --db ray.db --key-file cluster.key
# Real Ray acceptance gate (requires installation; no mocks):
python scripts/verify_ray_cluster.py --address local --islands 2
python scripts/verify_ray_cluster.py --address auto --islands 128 --distinct-nodes
```

API basis: [Ray actors](https://docs.ray.io/en/latest/ray-core/actors.html), [async ObjectRef](https://docs.ray.io/en/latest/ray-core/actors/async_api.html), [actor fault tolerance](https://docs.ray.io/en/latest/ray-core/fault_tolerance/actors.html), [actor options](https://docs.ray.io/en/latest/ray-core/api/doc/ray.actor.ActorClass.options.html). The direct Ray code and optional acceptance script are **not executed against installed Ray here**: pip reported no matching distribution in the available index. The module is importable without Ray; explicit Ray mode fails closed and does not silently use simulation. Physical scale/restart and version-specific runtime API compatibility require the acceptance command on real infrastructure.

## Evidence and boundaries

[Benchmark reports](cluster-benchmark-v22.json): 16 islands / 4 actual spawned processes / 128 proposals / 80 commits / 32 received migrations; 256 logical islands / 1 process / 1024 proposals / 768 commits / 511 received migrations; 3 islands / 2 actual spawned processes with Stage 3b enabled. Benchmark runs execute synthetic scheduler; no external comparison or speedup, and scores/migration counts depend on scheduling. Tests exercise actual process termination/recovery, response-loss simulation, asynchronous progress while one island is delayed, CAS and HMAC tampering, retry, automatic final drain, migration gate, forged metrics/missing gate, malformed migrant, mandatory challenge, and 256-island simulation. See [verification](verification-v22.txt). Existing v21 engine/worker/performance/checkpoint source bytes remain unchanged; v21 original checkpoint contracts preserved. v20 campaign contracts hash all canonical Python modules and therefore require matching old release. Existing unresolved upstream dependencies and external hardware/cluster acceptance remain open. CI workflows remain inactive.
