# v23 — Topological State-Space Evolution

Source: maintainer's 13-page specification `Dokument bez nazwy.docx`, SHA-256 `46b56e6ca8087b20211205c9e0ec58c3c41188ffe1e4d3966df2efb86214d5bc`, pp. 5–6. The supplied example initializes a singular all-ones matrix and substitutes a midpoint norm for geodesic distance. This implementation uses a finite, positive-definite conformal geometry and an actual weighted shortest-path metric on a graph. It does not claim exact smooth-manifold geodesics, unbounded dimension discovery, or automatic physical node provisioning.

## Representation and updates

`topology.TopologicalArchive` subclasses the canonical `engine.Archive`. Geometric features are the log-normalized validated AST node and operation counts. The two feature coordinates are quantized to a square mesh of side `2**depth` (depth 2–5; 16×16 default). A rolling window of at most 256 accepted observations (64 default) supplies local AST grammar frequency histograms. At each mesh vertex we pool its 3×3 neighborhood and calculate normalized Shannon entropy H. Finite-difference gradients of H set the conformal scale

`g = exp(2 phi) I`, `exp(2 phi) = 1 + strength * (H + ||grad H||²)`.

Gradient is expressed per lattice step. All eigenvalues are at least one; the identity metric results at strength zero. Interior finite differences approximate the Gaussian curvature `K = -exp(-2 phi) Laplacian(phi)`, with normalized domain spacing `1/(side-1)`. Boundary curvature is intentionally undefined. Curvature values are numerical estimates, not certified differential-geometric results.

Eight-neighbor undirected edges integrate the local metric using an arithmetic mean of endpoint tensors. Dijkstra gives a symmetric shortest-path **graph** distance, zero at identical vertices and obeying the triangle inequality (up to numerical rounding). The graph is connected. A cache holds at most 16 source distance maps. Distinct programs can map to the same feature coordinate; the distance is a metric on vertices, not on arbitrary source programs.

A quadtree replaces the original fixed 10×10 archive partition when enabled. Split a region only when the window contains multiple distinct mesh points with positive spatial entropy and sufficient observations. Local entropy and its gradient reduce the required count, with a floor of two. Each subdivision creates four children, with at most 1024 leaves at depth five; rebuilding from recent observations permits coarsening when diversity disappears. Old accepted lineage is never removed. At a transaction boundary, all lineage is deterministically rebinned by the new leaf mapping and the original fixed objective/Pareto dominance rule. The top four nondominated entries per leaf remain in the front. A fixed global score determines the champion independently of the partition. Updating topology freezes it during each in-flight actor batch and only changes the next revision. This is bounded adaptive discretization of a two-dimensional phenotype space, not unrestricted learned latent dimensions. Logical phenotype subregions are new archive leaves, not newly provisioned Ray actors.

The existing DGM/QD sampling weights are multiplied by `1 + graph_distance_to_champion`. A parent-conditioned inspiration is selected from retained elites by fixed score plus 0.25 times graph distance from the parent. In alternating proposal slots an AST-validated convex combination of parent and inspiration (or bounded symmetric residual/constant mutation) replaces the template operator; the existing proposal is used on other slots and as a fallback on AST-budget failure. Every proposal, including migrants, still passes the canonical cascade and optional v21 regression gate. Fitness, safety, audit and proposal caps are unchanged. Adaptation does not allow arbitrary candidate source execution.

## Cluster integration and integrity

Use `ClusterConfig(topology=TopologyPolicy(...))` or the `--topology` CLI flag. `--topology-depth`, `--topology-window`, `--topology-split-count` configure the discrete mesh/window. Default cluster path remains the v22 fixed grid. Both local and Ray adapters carry the geometry configuration and source hash; the driver reconstructs geometry from authenticated old lineage, independently reevaluates accepted candidates and reconstructs the new geometry, Pareto fronts and summary. Geometry hash, leaf count, curvature bounds and occupancy are checked before CAS commit. A timing profile uses the actual adaptive target cell (or the current global champion as fallback), not the old fixed descriptor. Migration retention receipts describe admission before rebinning. Reopening a completed store reproduces its report; asynchronous fresh runs need not reproduce the order of migration. Storage remains local single-driver SQLite and existing Ray worker trust boundaries remain. Geometry construction adds overhead and the driver recomputes it; no throughput/SLA claim. v22 cluster checkpoints bind old `cluster.py` and therefore require the v22 release. The original v21 engine/checkpoint/performance files are unmodified; exact whole-package v20 campaign contracts still require matching release.

```sh
# Use a pre-existing private 32-byte HMAC key and new DB.
python -m omega_x_evolution.cluster --backend process --islands 16 --rounds 3 --batch 4 --budget 192 --parallelism 4 --migration-interval 1 --topology --db topo.db --key-file cluster.key
# Identical flags and --resume to resume. Optional --performance-regression applies existing gate.
```

## Evidence

See `topology-benchmark-v23.json` and `verification-v23.txt`. Paired comparison uses identical seed 42, eight islands, four rounds, batch four, proposal budget 128, serialized dispatch, and actual spawned worker. Native occupied cells are not directly comparable across partitions. Common-grid descriptor coverage and common 16×16 phenotype mesh coverage are also computed over all accepted lineage, not just Pareto fronts. The adaptive strategy explores more feature bins but obtains a worse champion and holdout score on this single fixture. This does not establish a generalized quality or speed improvement. Additional 16-island/4-process run confirms integration. Simulated v21 timing tests verify actual adaptive-cell selection and driver reconstruction, not real GPU latency. Real Ray remains unverified. No physical cluster deployment or external scientific proof is claimed.
