# v34 — native local Llama-subset checkpoint adaptation

Base main `de9b7ca137d5e52cdc546838eabe3df43a08aeb4`. Existing v34 obligation; no new roadmap stage. This extends the real CPU decoder/LoRA and distributed-gradient evidence without replacing the optional Hugging Face backend or requiring its installation. Architecture reference: [Transformers v4.44.2 Llama source](https://github.com/huggingface/transformers/blob/v4.44.2/src/transformers/models/llama/modeling_llama.py); the implementation is native PyTorch and is independently numerically tested, not an assertion of complete upstream Transformers compatibility.

## Implementation and admission contract

`pip install '.[llm-native]'` installs the optional Torch/Safetensors/SentencePiece dependencies. Select `--backend native-llama --device cpu` with the existing `omega-x-llm-plasticity` CLI and existing operator authorization, key, model path and verified validation/retention splits. API: `load_local(path, device='cpu', backend='native-llama', rank=2, seed=42)`.

Strict subset: untied Llama causal decoder, separate unbiased projections, unscaled RoPE, RMSNorm, SwiGLU, grouped-query attention, right-padding and causal mask, no KV cache. Maximum context 512, coarse activation/logit/resource caps, parameter admission ceiling 4B (NOT validated at that scale). Reject unsupported model/config options, unknown keys, tied/missing/extra tensors, incompatible shapes/dtypes, nonfinite values, duplicate config keys, symlink artifact and unsafe shard name. Validate total parameter count and exact key/shape metadata on a meta-device model before allocating weight storage. Load F16/BF16/F32 into private FP32 CPU copies, strict state assignment, re-read the manifest and tokenizer after load. No silent random initialization or fallback; no network/model remote code. The operator directory must remain stable during loading; pre/post hashes detect persistent changes, not all adversarial replace-and-restore races. Native SentencePiece tokenizer file is required; bind exact tokenizer bytes, prompt, action IDs, config hash and backend source SHA to the encoder/campaign identity. Complete all six single-token operator continuations against the actual prompt and reject inconsistent tokenization. The ordinary HF mode remains default, with its prior scope and validation limitations.
