# v72 durable client epoch journal

Base main 9d6af1c9ec7303d486a5541bd7099c611ba3596a. Actual SQLite journal stores canonical transition data and hash-linked cursors, not secrets. The caller supplies independently trusted EpochPin bootstrap and a retained EpochCursor floor. Every read and update cryptographically replays stored append/rotation events using the actual v72 verifier; sequence, previous digest, canonical payload, next pin and cursor digest must match. Each advance or rotation is transactional with BEGIN IMMEDIATE, synchronous FULL and compare-and-swap on expected cursor. A fresh authenticated unchanged read consumes no journal event. No automatic creation on reopen, explicit 0600 initialization, existing private path checks. Replay after lost acknowledgement returns committed successor. Old witness receipts rejected after rotation. Restored snapshots and divergent histories fail relative to a retained floor. Joint rollback of all domains, external cursor custody, coordinated operational key cutover and production isolation are outside this increment. Journal intentionally bounded to 256 transitions and 16 KiB per event; fail-closed exhaustion, no compaction implemented. Trusted caller must generate fresh challenge per operation and retain the newest cursor outside the journal rollback domain. SQLite storage durability is not equivalent to HSM protection or real deployment.
