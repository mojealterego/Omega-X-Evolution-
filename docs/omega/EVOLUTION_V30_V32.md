## v30 — Reversible code epigenetics

`epigenetics.Switchboard` maintains a runtime bitmask for three optional functional blocks (`neural`, `associative`, `guided`). At any observed CPU, memory or queue percentage >=85 it disables them immediately; after two consecutive observations <=50 it restores the allowed blocks. Midband retains the mask and resets recovery streak. These thresholds and selection of blocks are engineering choices, not stated in the source. The mask cannot disable AST, formal safety, empirical cascade, audit, budget or quorum checks. All blocks are preinstalled trusted code, not mutable Python source or security controls. The swarm checks observations before every assigned proposal, actually switches the executed proposal mechanism and pauses neural updates while disabled; no recompilation. A bounded uniform proposal is the fallback. `Telemetry.sample` reads actual host CPU/memory with psutil; queue percentage is supplied by caller (live swarm uses remaining local assigned slots / fixed 256-slot cap). Host metrics are not cgroup or tenant resource accounting. Default is deterministic synthetic low-pressure input; explicit `--live-telemetry` samples at runtime, persisted measurements enable deterministic replay. Real telemetry was read; stress/recovery is controlled injection, not artificial physical utilization claims. Persisted results include mask, revision and recovery streak per slot; transitions are independently reconstructed on verification.

## v31 — Neurosymbolic formal checking

`proof_kernel` automatically normalizes validated pure u16 add/sub/mul IR into polynomials over Z/(65536). Each AST node has a sorted sparse coefficient witness in postorder, with all integers reduced modulo 65536. The generator and separate checker use distinct ring computations (modular dictionary incremental convolution vs Counter accumulation and modular reduction). The checker consumes each supplied witness, checks exact shape/type and recomputes each inference from validated children and the immutable arithmetic operations. It checks equal final forms, source hashes, term/work caps (1024 terms, 100,000 elementary operations per tree), and ignores no intermediate node. Equality is sufficient to establish extensional equivalence on all 2^32 input pairs; differing normal forms are **unknown**, not necessarily counterexamples. Bitwise operations outside this ring subset are unknown to the native checker; existing bitproof Z3 supports them separately. `optimize` automatically proposes strictly smaller subtrees/constants/variables, proves first, then checks 35 deterministic empirical points, and retains the original program on unknown. This optimizes fixed pure modular IR, not arbitrary Python/Lean formulas; no compiler equivalence guarantee. Four certificate pairs independently confirmed by existing Z3, including modular distributivity and cancellation; three reduce 5 AST nodes to one. `verify_certificate` tested with generator disabled and forged witness coefficient/type rejected.

Optional `--lean` generates a fixed Lean theorem over `BitVec 16` using the validated IR and `Std.Tactic.BVDecide`, with finite heartbeat/wall bounds. Only operator-installed trusted toolchain is used; no arbitrary input tactics, no `sorry`, no auto-install. Nonzero exit, warnings, timeout or absent binary fail closed. Lean is unavailable here (GitHub hostname resolution also failed); no Lean/Isabelle proof execution claimed. The adapter generates source for `bv_decide`, not a separately serialized Lean proof object. Lean's tactic checks SAT proofs and trusts its code generator as documented in https://lean-lang.org/doc/api/Lean/Elab/Tactic/BVDecide.html and https://lean-lang.org/doc/reference/latest/Tactic-Proofs/Tactic-Reference/ . Actual Lean acceptance and higher-order theorem proving remain open. Native certificate checking remains an independent executable formal gate. The swarm uses the existing v26 interval proof on binary64 scheduler candidates; u16 equivalence is a separate typed domain, not a proof of floating point arithmetic. No replacement of existing safety tests.

## v32 — Neuro-Symbolic Swarm (one-shot quorum coordination)

`swarm.Campaign` binds fixed sorted Ed25519 membership (up to 32), explicit session ID, seed, 1–16 epochs, <=256 slots/epoch, immutable source hashes and Python version. With n members and f <= floor((n-1)/3), quorum q=n-f. Every candidate plan assigns each numbered slot exactly once to a member, balanced floor/ceil allocation; any member can propose a different offset/permutation. Each peer verifies the signed plan, independently checks bounds and persists exactly one signed vote per epoch. SQLite FULL transactions and signed manifest reject missing/changed rows, concurrent double votes and conflicting proposals after restart. Any peer may collect q distinct signed votes and construct a canonical certificate. For two such quorums, |A ∩ B| >= n-2f > f, hence under the assumptions at least one honest voter would have to sign twice for conflicting plans. This proves quorum-intersection safety of **one-shot allocation**, not a full Byzantine fault-tolerant consensus liveness protocol. No leader election/view change, dynamic membership, automatic reassignment, or guarantee of progress when honest voters split. Unavailable assigned peers leave explicitly missing slots rather than double spending. Peer identities and databases must be protected by operator; whole-store rollback, copied keys and adversarial clocks are outside the model. Independent epochs, no global chain or replicated ledger. A new authorized campaign is required after deadlock or reallocation; there is no automatically multiplied search budget.

Actual execution: each peer runs only its certified slots; assignment determines RNG seed for mutation. Local MAP-Elites parents are qualified with v26 and fixed Cascade(42). A tiny 3-input/6-hidden tanh/6-output contextual reward network trains online via bounded SGD on observed local reward, with 20% uniform exploration. Enabled associative memory uses v25 history retrieval; guided mutation uses actual parent source. Load pressure (v30) switches these blocks off without removing formal/empirical/audit verification. Fixed score and seed budget never mutated. Each slot counts, including rejects. Signed report binds plan digest, epoch, worker, actual telemetry, optional verified parents and full results. `verify_result` independently recomputes candidate proof, metrics, exact assigned slots/masks and full deterministic search transcript; cannot attest truthfulness of physical telemetry. `BallotStore.execute` commits report and signed manifest before response, idempotent on retry/restart, rejects conflicting inputs and duplicate epoch execution. Low-level `work` is stateless and intended for test/protocol use; CLI requires durable store. Uncommitted computation may replay after crash; no externally visible mutation. Aggregation rejects duplicate worker reports and identifies missing slots. `export` integrates with v29 signed federation inbox and local requalification. Separate namespace does not insert anything into active v21 latency-gated campaigns. No claim of superior search quality from the neural router; benchmark demonstrates mechanism and fault accounting, not comparative performance. No BFT ordering of all discoveries.

Direct configured IPv4 endpoint (`/v1/vote`); Ed25519 authenticates every message. Loopback HTTP enabled for tests; nonloopback explicitly requires verifying mutual TLS contexts and trusted certs. No discovery, redirects, automatic network connections or credentials included. Single-request server and bounded payload/timeouts; private operator-managed networks only, not public DoS-resistant gateway. CLI uses a campaign JSON with `session` (64 hex), `members` (sorted public keys), `faults`, `slots`, `epochs`, `seed`; each peer supplies own private key file and local DB. Example using local paths:

```sh
omega-x-epigenetics
omega-x-proof-kernel
omega-x-proof-kernel --lean
omega-x-swarm --campaign swarm.json --key-file peer.key propose --epoch 1 > proposal.json
omega-x-swarm --campaign swarm.json --key-file peer.key --db peer.db vote proposal.json > vote.json
omega-x-swarm --campaign swarm.json --key-file peer.key certify proposal.json vote-a.json vote-b.json vote-c.json > quorum.json
omega-x-swarm --campaign swarm.json --key-file peer.key --db peer.db work quorum.json --live-telemetry > result.json
omega-x-swarm --campaign swarm.json --key-file peer.key verify quorum.json result.json
```

Other subcommands `serve --port` and `request --port --peer` exchange votes directly. Supply `--host`, `--ca`, `--cert`, `--tls-key` for non-loopback. Membership and files must be created by operator. No keys or runtime DBs included. Authentication does not imply that all peers are honest; the max-f fault model is explicit.
