# ONTOS OTCE — signed temporal capsule projection and replay optimization

Base main 1effc060709143ec5912ebfd9729af83fc710bf3. New versioned OTCEJournal is a separate journal format; it does not silently reinterpret legacy RCC. Scope pins tenant, encoder, dimension and fixed evolutionary epoch and distinct writer, revoker and reader public keys. Event chain and JCS bodies are signed; R0 projection and R1 exact ridge use existing ManagedJournal and RCC Statistics. Each capsule has valid interval, transaction sequence, cognitive time, forecast horizon, causal DAG depth, observation time, fixed evolutionary epoch and retention expiry. Derived input/output commitments and operator version are recorded in materialized metadata. Actual observed facts and forecast branches remain separate. Current revocation and retention overlay applies to historical reads and descendant contributions; observed lineage cannot depend on inferred/simulated/disputed nodes. R1 weights are recomputed from the selected eligible contributions, not incremental physical unlearning. Explain exposes selected capsule metadata, not payloads. Read requests are Ed25519 signed with exact query/operation, epoch, independent retained Fence and bounded expiry (64 clock units); rotated/retired reader keys cannot authorize new reads. Trusted caller supplies monotonic now and latest independent Fence, not the token's own fence. This is local authentication, not external IAM. Tokens are reusable within their valid interval and unchanged fence; one reader role per scope, no per-key weights/explain ACL. A signed assertion does not establish source truth. Scope/rotation keys are length-checked and strict verification rejects invalid points; provisioning an invalid reader can deny service. Operator must validate keys and clock source. No physical erasure or automatic promotion.

Capacity: 16 nodes, 8 reader rotations, 40 total events (16 admission + 16 revoke + 8 rotation). Compaction retains transcript and revocations. R2/R3/R4 are explicitly rejected. One fixed evolutionary epoch; migration, cross-epoch continuity and unbounded retention not implemented. Cache uses per-instance functools.lru_cache(maxsize=128) on exact (public key, message, signature) tuple, including verification failures. All replay state/chain/canonical checks and fresh read signature/epoch/fence/time checks remain. A reopened instance begins cold. Bounded memoization assumes trusted immutable verifier semantics during the instance lifetime. Does not cache authorization, external trust or result data; no persistent cache. Entire history still replayed; no O(1) claim.
