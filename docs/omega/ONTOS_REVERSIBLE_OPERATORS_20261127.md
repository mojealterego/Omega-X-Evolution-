# ONTOS RCC — scoped R2/R3/R4 operators (2026-11-27)

Base main 4d74cca65c5e1cd014efdf01dcbdea82b4af7433. OperatorJournal extends the existing sealed OTCE format; no new persistent capsule kinds, no reinterpretation of old state. Distinct signed r2/r3/r4 read operations; plain/sealed read endpoints reject these, so a dedicated operator token cannot silently be used as an ordinary read. Actual observed view only, existing selector and vault lock, exact independently retained source fence and trusted clock. All plaintext computation occurs after selection. Existing R0/R1 behavior unchanged.

R2: deterministic Unicode casefold/token postings index rebuilt for one signed logical-key shard from visible observed R0 capsules; sources are original output commitments. Excludes other keys, simulated branches, expired/revoked ancestry. No persistent plaintext index, semantic embedding, general operator registry or performance claim.

R3: bounded integer binary perceptron (label +1 when y>0, otherwise -1; update on nonpositive signed margin). Scope-wide selected R1 contributions, ordered by admission. Checkpoint records vault format pin, ordered prefix commitments and integer weights. Verify matching prefix by recomputing all prefix steps; mismatch of weights is rejected. If active-set prefix changes after revoke or expiry, rebuild from zero. Suffix replay equals complete recomputation. The validated prefix is not a throughput optimization (verification replays it). Checkpoints returned to caller, not durable model checkpoints or LLM unlearning. No guarantee of destruction of prior returned artifacts.

R4: separate native ManagedJournal receipt ledger, 16 permits maximum, provision one ledger per vault and separate authorized approver, trusted local operator must independently retain latest source and receipt fences. Permit binds signed read token hash, vault/ledger scope, recipient label, exact SHA256 of canonical returned value, nonce, issuance and expiry; verify Ed25519 approver distinct from writer/revoker/initial reader, also reject overlap with current reader after rotation. Commit consumed permit before returning one R0 payload. No data returned on failed/stale commit; concurrent use and restored old ledger are rejected relative to current retained fence. Uncertain commit can consume permission without release; never automatically retry. Receipt records authorization consumption, NOT delivery, contains signed hash/recipient metadata but no plaintext; low entropy digest can disclose information by guessing. No network delivery, actual recipient authentication, external export service or general irreversible operations. Trusted caller must respect recipient and retention. Returning authorized bytes to caller is the only R4 effect. Cannot retract copies already returned. Scope pin derives from vault format and approver; preventing duplicate independent genesis journals and rollback of all trust domains is a provisioning/retained-fence responsibility. No proof of global at-most-once outside this trust model.
