# OMEGA-X Evolution — v19–v20

Development snapshot 0.20.0.dev1. All twenty accepted roadmap stages now have bounded research implementations. This milestone does not certify production readiness or scientific novelty. The historical v4–v15 engine and checkpoint-contract files remain byte-identical, including `multilevel.py` and `recursive.py`.

## v19: dimension-aware scientific discovery

`science.Data` validates disjoint coordinate sets (train, validation, test), 1–8 named features, 1–512 records per split, finite bounded observations and four integer dimensional exponents (length, mass, time, amount). The search constructs monomials of degree 1–3 including the constant term when dimensionally allowed. Only monomials matching the output dimension are eligible; coefficients are dimensionless. Normalized greedy orthogonal pursuit and least squares choose a bounded sequence of supports on training observations. Validation selects the best support, favoring a smaller model within a train-derived numerical tolerance. Test is evaluated once, after selection. Maximum 12 fit attempts, 165 possible basis terms, no arbitrary execution or user-supplied code. `verify` reruns the experiment and compares the complete canonical report. No claim of general identifiability, dimensional completeness, noisy-data robustness or causality; users must supply compatible units and scales. The four built-in domains are synthetic, with known generating equations withheld from the fitting function.

```sh
python -m omega_x_evolution.science --domain kinematics --seed 42
python -m omega_x_evolution.science --dataset observations.json --degree 3 --max-terms 8
```

Custom JSON: keys `names`, `units`, `output_unit`, `train`, `validation`, `test`. Each row is `[[feature_1,...,feature_n],target]`. Example with dimensionless x and mass m has names `["x","m"]`, units `[[0,0,0,0],[0,1,0,0]]`, output unit `[0,1,0,0]`; use distinct coordinates and observations in every split. The complete campaign report records the fitted terms, numerical coefficients, units, fit attempts and held-out errors.

## v20: integrated research runtime

`runtime.Campaign` accepts 1–12 unique typed tasks across kinematics, mechanics, kinetics, dynamics, bit-program synthesis, numeric symbolic/neural/hybrid selection, and the original bounded scheduler evolution. A task can contain canonical `data_json` for the first six task types; scheduler is a fixed benchmark. Limits are checked before execution: <=4096 proposals per task, <=16384 in aggregate, <=400 epochs, <=200 million training work units, <=1.5 million characters of embedded datasets. Work units are accounting proxies, not FLOPs or dollars. The fixed search adapters retain their own bounds. CPU inference and NumPy training are defaults; optional Torch/Ascend/QNN policies use the existing verified router and an explicitly selected training backend. No arbitrary commands, external tool discovery, live LLM proposal calls, deployment or self-modifying code.

Each completed task is committed to the existing authenticated CAS SQLite checkpoint before publishing the content-addressed plan/result pair to graph memory. Replay republishes committed records idempotently, recovering interruption between the two stores. The contract binds the campaign configuration, input hashes, Python/NumPy versions and all canonical module bytes. Test results are not used to select a model within an experiment. `verify_campaign` independently reruns a campaign under the same local runtime and compares canonical JSON. It is intentionally fail-closed on nondeterministic hardware differences. No cross-database distributed transaction; replay repairs partial publication, not lost storage. Concurrent coordinators may execute duplicate work, but cannot both commit the same generation. HMAC does not detect whole-database deletion or rollback. Keys and databases need OS protection. The same original campaign and dataset bytes are required to resume. No irreversible actions occur during campaigns.

```sh
python -m omega_x_evolution.runtime --domains kinematics mechanics kinetics dynamics bits numeric scheduler --budget 1024 --epochs 400
python -m omega_x_evolution.runtime --checkpoint campaign.db --key-file checkpoint.key --memory memory.db --memory-key memory.key --stop-after 3
python -m omega_x_evolution.runtime --checkpoint campaign.db --key-file checkpoint.key --memory memory.db --memory-key memory.key --resume
```

Create and protect separate random keys (32–4096 bytes). Keep arguments identical between initial and resume commands except the stop/resume switches. `--campaign FILE` accepts the typed Campaign wire representation; `--verify-report FILE` independently replays a bare report. `campaign-benchmark-v20.json` contains the campaign input, report and memory retrieval evidence (the report field is the bare report used by verification). It covers all seven domains, checkpoint+graph reopen, replay equality, 14,208,000 training work units, 32/32 held-out u16 samples, numeric hybrid test RMSE 0.07622522020098542 and original scheduler score 0.5510961176601507 → 0.8237828727280723. Synthetic scientific RMSE: kinematics 1.2698997362391433e-15, mechanics 3.60154663657824e-16, kinetics 0, dynamics 2.089363828364446e-16. These are not independent external benchmarks.

## Backlog extensions

- `team_recovery.evolve_durable`: authenticated round commits of v9 populations, RNG, cached fitness, prior and migration history. The completed report matches JSON-normalized legacy v9 on the regression fixture; a final separate validation commit is replayable. The original v9 function remains unchanged for v10 compatibility. Use `omega-x-teams-durable --checkpoint team.db --key-file key --stop-after 1`, then the same options with `--resume`.
- `bitproof.prove`: accepts only validated u16 IR, encodes six operators into fixed-width QF_BV SMT-LIB, uses an isolated native Z3 solver with bounded timeout, and accepts only UNSAT as proof. SAT means non-equivalence; UNKNOWN does not establish proof. Covers all 2^32 input pairs mathematically for the particular program pair, not arbitrary source languages or compilers. Proof relies on trusted translation and solver. See `omega-x-bitproof --help`.
- `training.Trainer`: real Torch full-batch backpropagation in a separate process. CPU, CUDA, MPS and operator-installed Ascend targets. Uses NumPy reference training before the worker, and checks losses, output shape and predictions within fixed tolerances. No automatic device fallback for training. Timeout bounds the child operation; budget reserves both reference and Torch work. Training adapters are integrated in experiment and campaign plans. Default NumPy v18 plan JSON remains unchanged. Actual Torch CPU training passed; physical accelerator training did not run. Use `omega-x-training --device cpu --epochs 25` or `omega-x-experiments --training-backend cpu`. For hardware, compatible Torch/runtime must already be installed.
- `qnn.QNNBackend`: optional Qualcomm HTP adapter generates a static ONNX graph from validated MLP weights and uses the QNN execution provider with `backend_type=htp`, FP16 precision enabled and CPU EP fallback disabled; reference router rejects numerical mismatches. QNN API contract follows [ONNX Runtime documentation](https://onnxruntime.ai/docs/execution-providers/QNN-ExecutionProvider.html). `omega-x-compute --qnn --demo` probes optional availability. Requires operator-installed ONNX and compatible ORT QNN/QAIRT runtime; not a built Android native binary or validated Snapdragon deployment. Actual ONNX/ORT packages and HTP unavailable locally. Provider behavior tested only via simulation; export not executed in this environment. A missing provider is absent from inventory, not reported as hardware success. Inference may explicitly fall back through the router. Strict HTP-only policy is available via `Router.infer(...,prefer=('npu',))` and a QNN-only inventory.
- `semantic_memory.retrieve`: validated graph snapshot, TF-IDF and truncated SVD latent-semantic ranking with vocabulary <=256, rank <=16, lexical component and provenance expansion. Query must share vocabulary; not a pretrained embedding model. Optional `LocalSelector` calls a trusted loopback OpenAI-compatible server on a bounded port, with no redirects, secrets or tools, and returns only exact quoted substrings with authenticated node IDs and relation paths. A fabricated quote or citation is rejected. It bounds payload and response size; socket timeout is not a hard wall-clock bound for a malicious local service. Evidence relevance and truth are not authenticated by HMAC. Mock HTTP contract tested; no real LLM weights/service available. Use `omega-x-semantic-memory --db memory.db --key-file memory.key --tenant research --query kinematics`, optionally `--llm-port 8082 --llm-model local` when a trusted local server is running.
