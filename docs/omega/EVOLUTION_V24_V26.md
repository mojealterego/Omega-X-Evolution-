# v24–v26 — Annealed tensor policies, associative memory and safety synthesis

Source: maintainer `Dokument bez nazwy.docx` (SHA-256 46b56e6ca8087b20211205c9e0ec58c3c41188ffe1e4d3966df2efb86214d5bc), pp. 6–12. These are bounded classical implementations, not a physical quantum computer, consciousness, a general proof system, or an externally validated speedup. The new modes are opt-in and run in the actual v23 cluster actor. The canonical standalone engine and its v21 performance/checkpoint files remain unchanged. 

## v24 — Quantum-Inspired Annealed Policy Search

`annealed.TensorTrain.fit` computes real TT-SVD using NumPy. Context is a 4×4 discretization of the validated AST node and operation counts, with six mutation operators as the third axis. Reward is change in fixed aggregate score from the actual parent for an accepted candidate, or negative parent score for a rejected candidate. Sparse per-context means are shrunk to the global operator prior. SVD rank is capped at 3 (public TT fitter supports 1–4); rank-1 storage is 14 numbers rather than 96. The six approximate scores are evaluated together and sampled using a Gibbs distribution with 10% uniform exploration, temperature decreasing to 0.1. The chosen operator generates an exact bounded SEARCH/REPLACE patch using a recorded RNG seed. Topology mode retains its guided mutation on alternating slots; the fallback router uses TT. Candidate source, action and seed are checked against the fixed generator. All actual proposals count individually against the existing cap. No rejected candidate has permission to evade any safety or performance gate. This is a contextual offline mutation-policy adapter, not live LLM ensemble inference, a simulation of quantum amplitudes, or evaluation of an exponential number of programs for free. Across islands evaluation remains asynchronous.

`PYTHONPATH=. python scripts/benchmark_v26.py` compares four seeds at 64 proposals per strategy, using the same six generators, parent schedule, candidate-parameter seeds, and public workload; holdout is evaluated only for final winner. All four pairs had identical champion and holdout. TT required additional wall time (approximately 0.760 s vs 0.688 s over the four measured runs; timing illustrative, not a statistically controlled latency regression test). The rank-one tensor fixture reconstructs to max absolute error 9.95e-14 with 14 vs 96 scalar entries; this compression ratio is specific to that fixture, not arbitrary learned tensors. The small policy tensor is first materialized densely and recomputed on each selection; no asymptotic cost/quantum advantage is claimed. See the checked-in raw report.

## v25 — Holographic Memory Compression

`holographic.Memory` is a one-pass modern-Hopfield-style softmax associative read. The 128-byte signed int8 key uses stable BLAKE2b feature hashing of AST grammar and lexical unigrams/bigrams of the **parent context**; this fixes the source example's process-randomized `hash(text)` and mismatched context/patch keys. Similarity is normalized cosine on the quantized keys, logits beta=8, stable softmax over up to 64 input records. Keys need 128 raw bytes vs 1024 for the same 128 binary64 entries; the full provenance records are retained, so this is not an 8× storage claim for the whole archive. No trained embedding model; hash collisions are possible. Metadata includes parent identity/source, child expression, actual outcome, stage, score, reward, originating island and known operator/seed. Failed trials are negative evidence; accepted trials can also have negative gain. Neither instruction text nor a remote code patch is executed. The only candidate executor is the existing validated arithmetic interpreter.

Before choosing an annealed action, the actor reads nearest associations and applies weighted reward to the action scores; standalone memory mode can propose a positively rewarded retrieved expression, again through an exact patch and all admission gates. A rolling working set of at most 64 includes up to eight most recent local records from the direct predecessor's committed outgoing packet. Every outgoing packet is rebuilt from its origin's verified local history; imported records are not rebroadcast. Ring mailbox is latest-value, not global shared memory or reliable delivery of each trial. It includes successes and failures; provenance is checked by the driver's independent recomputation and existing HMAC/CAS snapshot trust boundary. No global Ray actor needed; the optional Ray transport carries this state with the regular island snapshots. This is non-gradient pattern transfer, not parameter distillation or consciousness. The original engine's SFT/DPO exporter remains untouched; raw trajectory evidence in the cluster can support later export but is not automatically a DPO dataset. Snapshot storage is append-only locally, with a bounded retrieval window; migration shares only the latest eight local records. No independent external LLM tested.

## v26 — Autonomous Formal Verification Synthesis

`safety_synthesis.prove` translates each validated AST into per-node, path-labeled numerical safety obligations (finite intermediate absolute value <= 1e12, and nonzero denominator before division). Input domain is every binary64 pair in [0,1]^2, not just a finite set of sampled test points. Conservative interval arithmetic encloses binary64 operation results by outward `nextafter` rounding, interval endpoints for monotone operations and all corners for multiplication/division; abs/min/max use sound interval bounds. Unsupported/invalid AST is rejected by the existing Expression validator. If an interval cannot prove an obligation, bisect the input box alternating axes, at most depth eight (up to 256 leaves). No candidate-provided axioms or host code. Unproved/unknown/unsafe is fail-closed, even when a program would pass empirical samples; dependency loss and conservative rounding can reject safe code. Bounds assume ordinary CPython IEEE-754 semantics, finite floats and round-to-nearest; proof is not about arbitrary Python, arbitrary inputs, timing, or all scheduler correctness. The proof record includes immutable policy identifier, source hash, proved flag, verified box/obligation counts, transcript digest, and explicit failure reason. Verify by deterministic reconstruction, no trust in claimed digest. This is a replayable interval proof certificate, not a proof object independently checked by Lean/Isabelle. The finite transition model checker enumerates reachable admission states and checks AG(admitted -> proof AND empirical AND performance AND audit); a deliberately bypassed transition falsifies the invariant. This verifies the abstract model, not whole-program refinement or complete security. No automatic revision of the safety axioms. 

When enabled, seed proof is explicitly checked, every attempted candidate and incoming migrant receives a certificate before empirical evaluation, and the driver reconstructs the proof before CAS commit. Existing stages 0–3 and enabled v21 timing gate are mandatory afterward; audit remains unchanged. The driver reconstructs feedback in attempt order and checks parent existence/code, score, acceptance, stage, source and known-operator seed. Rejected performance samples remain inside the trusted actor boundary; the driver checks reported rejection status but does not independently remeasure rejected profiles. A compromised worker could bias exploration via false negative measurements or proposal selection; cannot promote merely by declaring proof or fitness. Safety and resource restrictions are not evolvable.

## Usage and recovery

```sh
# use a new private database and a previously created private >=32-byte key
python -m omega_x_evolution.cluster --backend process --islands 8 --rounds 4 --batch 4 --budget 128 --parallelism 4 --migration-interval 1 --topology --annealed --holographic --formal-safety --db v26.db --key-file cluster.key
# optional --performance-regression keeps v21 same-host latency gate
# same arguments + --resume to resume; optional --stop-after N to stop after N new commits
python -m omega_x_evolution.safety_synthesis -- '-(x+y+(x-y)*(x-y)/(.01+x*y)+2)'
```

New feedback/proof modes have a conservative combined cap of 8192 proposal and potential migration operations per campaign and existing per-island 16 MiB stored-state cap. Memory query keys are built from the latest bounded window, not all records; no claim of constant-time retrieval. Source and policy are bound into checkpoint contract, invalidating older cluster checkpoints; use matching earlier versions. `engine.py`, `workers.py`, `performance.py`, `checkpoint.py` are not modified. New dependencies beyond the existing project NumPy are not needed; Ray still awaits actual installation and deployment. New full-package v20 research checkpoint contract also changes with module set. Timing is not deterministically replayable across new executions; completed persisted reports do replay. Model selection, memory and proof flags are explicit and default off to preserve previous benchmark semantics.

## Evidence

- Paired tensor experiment: 512 individually charged proposals, four pairs; identical average champion and holdout, no proven quality advantage.
- Real process integration: eight logical islands, four local spawned processes after restart, 128 proposals and 40 durable commits; stopped after 11 commits then resumed. 156 candidate/migrant formal checks and 5052 checked obligations; 64 foreign records present at completion. Score 0.5591341064 -> 0.8500093647, holdout 0.9290830397. No regression-gate timing in this integration benchmark; separate simulated timing test exercises the enabled v21 gate.
- Negative controls: invalid AST, hidden pole, intermediate overflow, forged proof/reward, seed mismatch, forged transfer, invalid modal transition, v21 rejection despite valid proof. See `verification-v26.txt` and `benchmark-v26.json`.
- No physical Ray, GPU, NPU, external LLM, quantum execution, or higher-order theorem prover used. Upstream dependency and external validation backlog remains in closure register. CI workflows remain inactive.
