# v33–v35 — Axiomatic discovery, weight plasticity and infrastructure orchestration

Source: maintainer `Dokument bez nazwy.docx`, p. 13 (SHA-256 46b56e6ca8087b20211205c9e0ec58c3c41188ffe1e4d3966df2efb86214d5bc). These are bounded operational extensions. The existing v26 cluster and v32 swarm source contracts are unchanged. No external infrastructure is provisioned and no unrestricted self-modifying agent is introduced.

## v33 — Zero-Shot Axiomatic Discovery

`axioms.discover(seed,budget)` constructs a pool of validated modular u16 programs from the existing pure IR and seeded grammar composition; no labeled identity pairs are supplied. It proposes pairs from collisions on four Boolean-coordinate probes and general random pairs, without conflating signatures with proofs. Each conjecture is tested on 25 boundary and 32 seeded interior points. A witnessed inequality is refuted; independent v31 constructive polynomial certificates are required for native proof. Remaining cases are unknown, not theorems. Proof is sufficient over every pair of u16 values (2^32), not proof for arbitrary integer arithmetic or executable compilers. `classify(...,smt=True)` optionally asks the existing bounded Z3 bitvector solver, distinctly records solver results; no solver-only claims enter the native discovery report. `verify` independently checks witnesses and deterministically replays the bounded search. `publish` accepts only verified native reports and records proofs and provenance in authenticated GraphMemory, idempotent content-addressed nodes. This is a finite grammar search, not discovery of new physical laws or arbitrary consistent axiom systems.

`structures(order,budget)` enumerates Cayley tables of order 2 or 3, checks all triples for associativity, determines two-sided identity, commutativity and inverses; group membership requires all group axioms. Reports exact examined count and whether exhaustive; labeled table counts are not counts up to isomorphism. It does not assume that every operation table satisfies the axioms. Budget <=19,683 tables; conjecture count <=1024. Default discovery fixture seed42, 256 proposals: 46 proved, 96 refuted, 114 unknown, 411 generated programs. Order 3 exhaustive: 19,683 labeled tables, 113 associative, 3 group tables. An additional seed7 run was used in tests. Results are rediscoveries of known bounded algebraic properties, not mathematical novelty claims.

## v34 — On-the-Fly Weight Plasticity

`plasticity.Policy` freezes the v32 3-input/6-hidden/6-output contextual reward network, with 54 base weights and adapter matrices A(6,r), B(r,6), r in {1,2}. Inference is `h @ (V + A @ B)`; full-batch gradient descent changes only A/B on the observed action reward, with finite values and magnitude bound, 1–400 steps/update, <=16 updates/ledger. Base hash is recorded. Proposal selection affects only which bounded mutation is proposed; formal totality, fixed Cascade(42) and actual reward reconstruction remain mandatory. `choose` emits a replayable v25 trajectory, not an automatic update to a running campaign. `collect_store` reads verified seed-42, formal-safety, annealed cluster snapshots, replays operator seeds and recomputes scores; excludes incompatible, missing or unqualified rows. Does not mutate source clusters. The data bounds are 64 rows per training/validation/retention split. Reject repeated trajectory IDs across data and identical parent ASTs across splits. This does not prove absence of semantic overlap. Train/validation/retention used for bounded update; separate final evaluation is caller-controlled, not used for promotion. Validation must strictly improve; retention MSE must remain within 0.002 of both active and frozen baseline. This tolerance and rank range are engineering choices. Results record candidate and split hash. `Plasticity` uses HMAC CAS checkpoint and exclusive POSIX lock; request ID binds input, reserve steps before training, preserve reservations across restart, reject conflicting request, return committed identical response on replay. Interrupted reservations remain charged; explicit rollback resets to initial adapter without replenishing budget. Requires explicit training/rollback authorization. Repeated rollback increments audit count. Trusted operator controls keys and directory; full checkpoint rollback/deletion outside HMAC guarantee. The lower-level trainer is an offline research API, not an authorization sandbox.

Benchmark uses actual proposals from disjoint syntactic parent sets: 36 training, 36 validation, 36 retention, 36 final test. Seed42, rank2, 400 steps, 24 trainable weights. Validation MSE 0.0191906750 -> 0.0186495437, retention 0.0117398955 -> 0.0112051984, final test 0.0101385345 -> 0.0086709803. The adapter was promoted; rollback restored initial adapter with all 400 steps still charged. This is actual small-router LoRA, not LLM/transformer weight training, nor established end-to-end search superiority.

## v35 — Autonomous Infrastructure Orchestration

`infrastructure.Orchestrator` executes three preinstalled workload kinds (`axioms`, `scheduler`, `plasticity`) only, no caller-supplied command, shell, URL or remote resource. Immutable policy caps cumulative CPU-second reservations (<=600), job count (<=16), per-job wall time (<=120s), parallelism (<=4), address space (256–2048 MiB per child). Operator must explicitly authorize creation, run, stop and recovery. Atomic HMAC CAS reservation of the entire batch before spawn, ledger key binds job id and payload; repeat returns stored result, collision fails. Separate POSIX lock prevents competing launchers. Every direct Linux subprocess has sanitized minimal environment, closed file descriptors, no stdin, fixed module dispatcher and child RLIMIT_CPU/AS/FSIZE/CORE, job wall alarm and checked parent-death SIGKILL via prctl. Parent additionally polls wall deadline and irreversible private-directory stop marker, terminates active children, cancels pending jobs and waits. Optional host telemetry reduces future launch parallelism to one under >=85% CPU/memory; it does not stop already running work solely because of pressure. Budget counts reservations rather than actual CPU consumption, never refunds failed/cancelled/interrupted jobs. CPU-second caps apply to each direct trusted worker, not arbitrary subprocess trees; memory address-space limits are not actual aggregate RSS or cgroup quotas. Runtime has no network sandbox; must not be exposed to untrusted code. Local trusted workloads do not spawn arbitrary additional processes in these paths. Launch time and early interpreter startup precede worker limits; parent deadline and worker recheck bound normal operation. Stop marker and database directory are trusted local operator-controlled state, not tamper-proof external stop broadcast. Interrupted reservations marked on recovery, no implicit rerun or refund. Loss of host/storage needs operator backup. Linux only; no remote provider, service discovery, deployment, BFT or automatic cloud scaling. Explicit external allocation is an open requirement; no credentials or paid API invoked. Direct worker entry point is internal trusted code, not a security sandbox against a user who already controls the execution environment.

Benchmark: actual local subprocesses executed all three workloads with 15 CPU-seconds reserved, peak parallelism 2, three distinct child PIDs, all exit 0; repeated request returned identical ledger results. Tests stop a live batch, force-kill coordinator and confirm child termination, recover interrupted reservation and run a new explicitly authorized job, reject budget overflow and unregistered workload. No real external infrastructure activation.

### Run the modes

```sh
omega-x-axioms --seed 42 --budget 256
omega-x-axioms --structures 3 --budget 19683
omega-x-plasticity --steps 400 --authorize-training
omega-x-infrastructure --help
```

Durable commands use private operator-supplied key file (>=32 bytes), database, `--create` once, and explicit `--authorize-training` or `--authorize`. Plasticity uses `--dataset` JSON `{train,validation,retention}` of v25 trajectory records; `--request-id` for idempotence, `--rollback` to restore initial weights, `--inspect` to read state. Infrastructure uses `--policy` JSON matching `Limits` and `--jobs` JSON array matching `Job`, e.g. `[{"id":"study","kind":"axioms","cpu_seconds":5,"wall_seconds":10,"seed":42,"budget":256}]`. `--stop` is irreversible for this ledger under the private-directory assumption; a fresh authorized ledger is needed for further work. `--recover` does not launch anything.

Evidence: `PYTHONPATH=. OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python scripts/benchmark_v35.py`; tests in `tests/test_omega_v35.py`, logs summarized in `verification-v35.txt`. No Actions activation. Earlier physical Ray/QPU/NPU/Lean/BFT and full upstream dependency gates remain open.
