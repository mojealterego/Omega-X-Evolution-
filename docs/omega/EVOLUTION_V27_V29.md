## v27 — Quantum-Assisted Annealing

`quantum.Problem` represents up to 32 binary choices representing archive candidates, with 1–8 selected, 1–16 integer descriptor coordinates (0–100) and fixed quality 0–1000. Minimize

`E(z) = -Σ q_i z_i - Σ d_ij z_i z_j + P (Σ z_i - k)^2`,

where `d_ij = floor(2 * L1(f_i,f_j)/dimension)` (0–200), `P = 1 + Σ q_i + 200 n(n-1)/2`. All infeasible selections have positive energy, all feasible selections have non-positive energy; no caller-provided objective or executable code. The constant `P*k*k` is removed from the solver submission and restored locally. Cardinality-preserving classical swap annealing never generates infeasible states, records its best feasible solution, and counts all objective evaluations. Exact enumeration, capped at 100,000 combinations, provides a local reference. `select_elites` ranks/deduplicates the actual MAP-Elites front (top 32 unique programs), derives the two AST features and three fixed evaluator metrics, and selects up to eight diverse representatives. Does not change fitness/admission policy. Federation export uses this selector; no modifications to the original cluster transaction loop. No automatic quantum execution.

`hardware` validates a one-shot operator-owned sampler response and recomputes energy and cardinality, rejects malformed samples, ignores infeasible samples, and refuses use unless `authorized=True` (max 256 reads). Optional `dwave_sample` invokes Ocean `EmbeddingComposite(DWaveSampler(...)).sample_qubo`, with failover disabled, request timeout 15s, polling timeout 90s, TLS verification on. One application-layer submission per call; SDK transport retries/provider billing outside our control. Provider configuration/credentials and quotas are operator-owned. Timeout does not guarantee cancellation of an already submitted job. `select_elites(..., sampler=dwave_sample, authorized=True)` compares the external feasible result to the same classical problem and retains the better. No fallback on external failure. `export_store` accepts the same explicit parameters. Use `python -m pip install '.[quantum]'` and `python -m omega_x_evolution.quantum --qpu --authorize-paid-submission --reads 64` **only with explicit budget/authorization and configured provider**. Default CLI is local. Actual physical QPU, Ocean dependency, provider charges, embedding scaling and performance are open. SDK API basis: https://docs.dwavequantum.com/en/latest/quantum_research/example_sat_constrained.html and https://docs.dwavequantum.com/en/latest/ocean/api_ref_cloud/resources.html .

`PYTHONPATH=. python scripts/benchmark_v29.py` uses four 16-variable/8-feature instances selecting four items. Exact 1820 objective evaluations each. Classical annealing and independent uniform random subset search receive equal 513 evaluations each. Annealing matched all four exact minima and random matched one; actual wall times recorded, not a hardware or general NP-hard performance claim. Exact and classical operation counts are not quantum read equivalence.

## v28 — Autonomous memory architecture synthesis

`architecture.Index` authenticates a local `GraphMemory` snapshot (up to 512 nodes, 4096 adjacency entries), freezes its content digest and builds lexical term sets and 128-dimensional signed hashed character-trigram associative vectors. `Plan` is a typed composition of lexical retrieval, associative retrieval, weighted fusion, 0–2 hops of provenance spreading with discrete decay, bounded ranked output and exact paths/relations. No generated executable source; all stage implementations fixed and only bounded combinations synthesized. The default baseline is pure lexical retrieval. Search up to 56 typed plans on explicit training retrieval cases; rank by reciprocal-rank quality then counted retrieval operations. A single training-selected challenger competes against baseline on validation; promotion requires higher MRR, or equal MRR at lower work. Test labels are never consulted for ranking/promotion. Distinct normalized query feature sets required across splits; known target node IDs (supervised retrieval cases) remain in the shared corpus. This is not a proof of semantic generalization or discovery of arbitrary neural/memory algorithms. The work proxy counts lexical comparisons, associative vector components and examined edges, not exact wall time or energy. Corpus index construction and encoding have their own cost. Training, validation and test size bounded to 64 each; aggregate work cap. Selected plan and DAG, all train scores, snapshot hash, val/test report exported as JSON.

Eight synthetic domains, 16 nodes and 8 typed provenance edges, with 24 distinct queries (8 per split). The selected plan enables one-hop graph diffusion, lexical weight 1 and associative weight 0; MRR 0.5 vs lexical-only 0 on validation and heldout test. Work: 136 vs 128 units on each eight-query set. Fixture intentionally tests provenance-only answerability; no claim pretrained embedding, external benchmark superiority or universal architectural novelty. Actual federation `Peer.publish(memory)` creates provenance nodes using signed inbox packets, source/public keys, sequence and locally verified artifact proof/metrics; publication is idempotent content-addressed but across several graph transactions, retry after interruption. `Index` supports that published graph as well as existing GraphMemory data.

```sh
python -m omega_x_evolution.architecture --db graph.db --key-file graph.key --tenant research --cases queries.json --budget 56
```

Query file format JSON object `{ "train": [{"query":"...","target":"<64 hex node ID>"}], "validation": [...], "test": [...] }`. IDs from actual authenticated graph. No external model required.

## v29 — Swarm Federation

Each independent peer has its own Ed25519 private key, allowlisted public keys (max 32), and local SQLite inbox; no central signing authority or cluster coordinator. Message `{body,signature}` binds protocol schema, evaluator/source hashes, Python patch version, sender, intended recipient, monotonic sequence, and 1–8 distinct restricted expressions. Receivers authenticate the packet and exact allowlist, re-run immutable v26 totality proof and full local `Cascade(42)` for each expression; do not accept claimed remote score or proof. All-or-nothing inbox transaction. Peer stores signed manifest of all packet digests; verify manifest, signatures, sequence monotonicity, caps on every open/receive. Replay of identical signed packet yields signed duplicate receipt, zero new admissions; same sequence with other content or stale out-of-order packet rejected. Sequence allocation is operator-managed; no automatic outbox, routing, consensus, peer discovery or retransmission. Sender key revocation / allowlist changes require a deliberate new store, and full DB rollback remains outside guarantees. Each accepted envelope <=64 KiB; 128 packets/store, 1024 received artifact entries maximum. Rebuild local fixed Pareto archive from independent proofs. `Peer.evolve` uses received programs as actual parents for up to 256 local bounded proposals, then returns signed selected front; no mutation to live source cluster and no automatic sending. `export_store` reads existing authenticated cluster snapshots, gathers front, deduplicates by code, rechecks top 64, selects up to 8 via v27; no modification to cluster source/checkpoint. Local federation archive uses its own fixed evaluation workload, not the original campaign's holdout or measured v21 latency gate; no insertion into existing campaign without its own authorization/gates. This isolation is intentional. No arbitrary code execution; `Expression` interpreter, v26 and local empirical gate mandatory. No remote secrets, model weights, or source beyond chosen restricted expressions.

Direct IPv4 endpoints configured by operator, no URL in packets, no redirects/discovery. HTTP POST `/v1/exchange`, body cap and socket I/O timeout, signed receipt bound to packet digest and receiving public key. Loopback plaintext for development; non-loopback requires mutual TLS on listener and a verifying client context (CLI requires CA, cert/key). Bounded single-request server per peer (not internet-facing hardened gateway/DoS protection). Use private networks, operator-provisioned certs and network limits. TLS identity is separate from Ed25519 allowlist. Real tests exercise TLS handshake locally and reject missing client cert; no external network deployment. Node keys and DBs never included in release archive. Requires cryptography (`.[federation]`).

```sh
# Create private key in operator-controlled directory, once per peer.
python -c 'import os,secrets; fd=os.open("peer.key",os.O_CREAT|os.O_EXCL|os.O_WRONLY,0o600);os.write(fd,secrets.token_bytes(32));os.close(fd)'
python -m omega_x_evolution.federation --key-file peer.key public
# Each peer uses its own DB, key, and explicit counterpart public key.
python -m omega_x_evolution.federation --key-file peer.key --db peer.db --allow OTHER_PUBLIC_KEY serve --port 8089
# Send signed packet generated by sender:
python -m omega_x_evolution.federation --key-file sender.key pack --recipient RECEIVER_PUBLIC_KEY --sequence 1 -- '-(x+y)' > packet.json
python -m omega_x_evolution.federation --key-file sender.key send --port 8089 packet.json
# On receiver, evolve imported elites and export a reply:
python -m omega_x_evolution.federation --key-file peer.key --db peer.db --allow OTHER_PUBLIC_KEY export --recipient OTHER_PUBLIC_KEY --sequence 1 --evolve 32 > reply.json
```
