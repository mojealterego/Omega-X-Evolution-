# ONTOS OTCE — envelope encryption and bounded key lifecycle (2026-11-27)

Base main e64a48f89d8552aaef344ad1d3651ca0a93dcca5. Adds opt-in SealedOTCEJournal, using the actual ManagedJournal, OTCE temporal selector/reducer, Ed25519 and exact R1 Statistics. Separate format pin and event signature domain bind an independently provisioned vault ID and Scope. Plain OTCE state/event format remains unchanged. No automatic migration from existing plaintext histories.

Per-capsule random 256-bit DEK, AES-256-GCM with random 96-bit nonce; AAD binds immutable capsule metadata, vault/scope, logical key and key ID. R0 values and R1 vectors/labels are encrypted before signing and before durable storage. Journal metadata (including logical keys, lineage, time, source commitments, size, ciphertext and IDs) remains visible; metadata must not contain secrets. Separate private SQLite vault holds wrapped DEKs under external 256-bit KEK (AES-GCM, independent random nonce and scoped key ID AAD). HMAC marker detects wrong scope/vault/KEK. No KEK written to database. Use high-entropy independent KEKs and vault IDs; key custody/provisioning are operator responsibilities. File paths and in-process caller are trusted, all cooperating operations use flock and private directories; no OS isolation against privileged hostile users, no HSM or external KMS deployment.

Signed writes verify actual capsule schema and ciphertext domain. The shared reducer validates signed metadata without decrypting history. Only after signed read authorization, current Fence, clock, reader epoch and lineage/retention selection does the gateway decrypt R0 or R1 and calculate exact ridge weights. Never serves partial weights on decryption failure. Explain metadata intentionally remains readable by authorized reader. Put commits wrapped key before journal append; on uncertain outcome retains key. Explicit reconciliation/purge at newest independently retained Fence removes abandoned keys and keys of revoked/expired nodes and descendants; stale callers cannot purge a newly committed key. Revocation and purge are separate operations: revoke denies reads immediately even before purge. SQLite secure_delete=ON, DELETE journaling, synchronous FULL and transactional KEK rewrap; a crash may leave old journal blocks, backups and copies. Rewrap does not change the journal Fence or establish a persistent external KEK epoch; external custody and atomic provisioning of the new KEK required before call. Restoring an old vault under its old KEK is outside the cryptographic-erasure guarantee; current logical revocation still enforced by independently retained journal Fence. No forensic sanitization guarantee, memory zeroization, secret deletion from backups or exported plaintext, or proof of physical erasure. True cryptographic erasure additionally requires elimination of every recoverable DEK/wrapped-DEK+KEK pair. No claims of cryptographic erasure of earlier plaintext stores.

Existing 16-node, 40-event budget retained; key vault maximum 64 records including abandoned keys, 512-byte canonical plaintext budget and existing 2048-byte event body budget both apply. Separate format cannot be opened as plain OTCE. No R2–R4 execution, changed-encoder migration, external authorization service, or production deployment.
